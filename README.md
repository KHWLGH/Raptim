# Raptim

Raptim —— 基于 Lucy 重构研究推进的 Windows 本地启动器，Rust + Slint 应用工程。运行方式见下文“运行”一节，验证方式见“开发验证”。

主界面空白处右键可选择小／中／大图标（默认最多五／四／三列，窄窗自动减少）或列表，立即保存。分组标签横向滚动显示完整名称，子分类名称自动换行；两栏放不下时一律靠滚动查看，栏尾不再有「…」选择菜单。分组栏与子分类栏末尾各有一个「＋」就近新建分组／子分类，两栏的空白处都不弹菜单（新建只走「＋」和分组／分类项自己的右键），行为保持一致。运行时仅保留托盘入口；标题栏没有最小化／收起控件，唯一的“关闭”就是隐藏窗口，托盘／热键可以再次呼出。托盘另提供「暂停自动隐藏」与「暂停游戏勿扰」两个可勾选入口，设置页的勿扰标签有同一个开关；放行只作用于本次运行，不写数据库。

设置、项目编辑、名称编辑及文件选择打开期间暂停失焦、贴边、启动后隐藏及普通全屏自动隐藏；明确配置的严格保护程序仍优先（列表最多 100 项，前台窗口命中任一路径即进入保护）。关闭辅助窗口后重新开始隐藏计时。

关闭前台设置、名称或项目编辑窗口时主动将焦点交回主窗口，保留固定状态；后台关闭不抢焦点，已隐藏的主窗口不会被重新唤出。

## 运行

开发环境：Windows x64、Rust 1.92+、Visual Studio C++ Build Tools 与 Windows SDK。本次使用 Rust 1.98.1；最低 Rust 版本尚未实测。关于页的编译器版本由 `build.rs` 在编译时取本机 `rustc --version`，所以每台机器自建的二进制这一行都不同。

```powershell
cargo run --release --locked
```

程序位于 `target/release/raptim.exe`。使用 Slint 1.18.0 Fluent 控件、winit Windows 后端和软件渲染器，不依赖 WebView、JavaScript 或 C#。

默认直接在 **EXE 同级目录**保存 `raptim.db`（含设置和项目图标），不创建 data 子目录、不写 AppData。首次运行建立版本 2 的新库，内含“常用”分组及真实的“默认分类”。

```powershell
# 便携模式：与默认相同，直接写 EXE 同级目录
.\target\release\raptim.exe --portable

# 独立数据目录：适合开发和试用
.\target\release\raptim.exe --data-dir C:\Temp\RaptimTrial
```

目录不可写或数据库无法识别时会报错，不暗中切换目录。

## 近期实现记录

- 数据页只剩“导出／恢复”两个动作：应用内“备份”整套删掉——设置里的按钮、“数据”子菜单项与命令号、`Store::backup`、恢复前自动写的 `before-restore-*.db` 快照、`rusqlite` 的 `backup` 特性和再没人引用的 `ui/icons/backup.svg`。理由是用的人自己在数据目录层面备份更直接（见“数据恢复”）。被替换数据这件事本身仍在事务里，失败自动回滚；删掉的只是“恢复成功后反悔”的那一份快照。
- 贴边展开时的圆角／阴影跳变：**应用侧已经清账，剩下那一下在合成器**。第一层原因是装饰函数被反复调用——`decorate()` 曾在每次召唤、每次展开、每次 resize 上无条件重写 `GWL_EXSTYLE`、经 winit 重设按钮掩码、重写四项 DWM 属性并清一次窗口区域；再加上层级切换走 winit 的 `set_window_level`，它按 winit 自己的窗口状态**重算两个样式字**，把 `WS_EX_TOOLWINDOW` 抹掉，于是下一次 `decorate` 必须写回来，而这次写回正落在窗口还在滑的那一拍。现在每笔改框写入都对着 HWND 的当前状态判断（样式位、是否装着区域、在哪个层级），winit 那条重写样式的路径不再被调用，`SetWindowRgn(NULL)` 只在确实装着区域时才做且带上重绘，焦点事件不再重写边框色。顺带修掉同源缺陷：贴边滚一轮后启动器重新出现在任务栏／Alt+Tab。机器验收把账记成数：一次收起＝1 笔写入、一次展开＝1 笔，就是层级那两下；把“始终置顶”打开后**收起／展开都是 0 笔**，而桌面上的跳变仍在——所以残余那一下不是本进程发起的调用，是 DWM 的圆角遮罩与“每个刷新都挪一次窗口”之间错的那一帧。`check_edge_motion_frame_state` 把这几种情形都钉住，包括“第二次召唤一笔都不发”（靠 `FRAME_WRITES` 计数器证明：状态相等证不了没重建）。圆角本身只能到桌面上看，取证脚本与判读见“开发验证”第三层。
- 数据库升到版本 2：图标从 `entries.payload` 的 JSON 文本移到独立 `icon BLOB` 列，重复目标判定键 `dup_key` 在写入时物化，校验不再读全表；JSON 导出的 `icon` 改 base64。图标回填也不再触发全量 `refresh()`，而是就地替换 blob 并只让可见带重解码那一条。
- 名称编辑与应用选择是主窗口／编辑器窗口内的覆盖层，不再有独立顶层窗口；设置窗口按需创建。启动复用已校验的数据快照。主网格按行虚拟化，图标在后台按可见范围解码并统一缩到 128 像素（新存入的图标同样以 128 像素保存，旧库里的 256 像素图标读取时降采样），解码缓存上限 24 MiB，完全隐藏时收缩到只剩可见范围。
- 支持手动选择外观主题（跟随系统／浅色／深色）；处于贴边收纳态时直接读取系统颜色配置并在露边态绘制柔和的统一边框与指示条。`src/ui_commands.rs` 与 `src/app_session.rs` 为标准 Rust 子模块，`slint::include_modules!()` 统一放在 `src/lib.rs` 中复用编译结果。
- 第二实例改用系统事件通知；完全隐藏时不轮询，贴边收纳只做一次光标位置判断（光标远离揭示带时间隔 32 毫秒，靠近时 16 毫秒），贴边动画按帧时钟推进。热键、托盘和第二实例继续经过统一保护策略。
- 记忆主窗位置、尺寸、贴边方向及最后分组/分类；分类滚动位置和键盘焦点在当前会话中保留。显示器变化时将窗口限制在可见工作区。
- 搜索增加“全部／当前分组／当前分类”。仅从项目区空白右键或“更多 → 多选整理”进入多选；支持 Shift 连选、Ctrl+A 和分层 Esc。批量整理面板按三等分列排布，全选／完成与复制到…／删除上下对齐；批量移动/复制使用分组与分类树，卡片里的执行按钮与其余确认框一样高亮，确认后执行；成功后保留整理模式并清空选择，失败保留目标与选择。重复目标会取消整批操作，删除不影响原文件。
- 菜单按操作语义分段：分隔线由同一套 owner-draw 通道绘制（9 逻辑像素高、禁用项，所以鼠标和键盘都会跳过它），子菜单里的分段同样生效；空白右键那一段整体复用到标题栏“更多”，窄窗口不再需要赌运气点空白。
- 菜单树与命令归属搬到库里的纯数据（`raptim::menus::tree` / `region`），二进制只负责读状态填 `MenuContext`、开弹窗、按 `Region` 分派；菜单内容因此可以离屏断言，不再只能靠真点一次。顺带修掉两处一直存在的缺陷：八个菜单项沿用 `action()` 的默认字形（一张人像，包括分组／分类的“删除…”），以及一处恒为真的排序判定——排序项现在按 `MenuContext::can_move_up` / `can_move_down` 置灰，这两个字段取自 `Store::move_entry` 的真实边界。
- 接入原生 OLE 文件和浏览器网址拖入；落在分类节点时进入该分类，其余位置进入当前分类。网址可省略协议（`example.com` 按 `https://` 补全），仍只接受 http/https，不联网获取标题。编辑窗口仍支持单张图片拖入。
- 窗口位置和“始终置顶”是本机状态，不随 JSON 导出。
- “呼出与隐藏”新增“窗口始终置顶”，允许同时贴边收纳；标题栏临时钉住仍会暂停自动隐藏。保护解除后，原来可见且未钉住的贴边窗口只恢复收纳入口，不自动展开、不抢焦点；手动隐藏不会自动恢复。
- 工具与项目提示统一使用主题表面、细描边和紧凑圆角。项目提示显示名称、完整路径或网址与备注，备注最多六行。编辑窗在原生句柄就绪后注册图片拖入，关闭时释放，并丢弃旧编辑会话的拖入回调。
- 精简移除限制改动范围的实窗回归（`src/app_regression.rs`）、离屏像素/坐标/文案回归（`tests/offscreen.rs`）及菜单像素/字形锁死测试，仅保留核心模块逻辑的基础单元测试。
- `verify.ps1` 使用标准 `cargo fmt --check`、`clippy`、单元测试及 release 构建检查全部模块。

## 当前功能

- 标题栏下方横向分组、左侧纵向分类；默认每行四个项目，窄窗自动减少列数，名称最多显示两行，悬停显示完整名称和路径。使用 Fluent 实色层次和系统圆角，移除染色外框。编辑与设置使用辅助窗口，关于并入设置标签。
- 分组、分类通过就近新建按钮和居中名称窗口创建、改名，不挤压项目区、同级排序、跨分类拖放、子分类移动及删除继续支持。**F2** 是就地入口：焦点在分组或分类上时直接在栏内改名（Enter 提交、Esc 取消），在项目卡片上时打开它的编辑窗。删除时可以先把内容迁移到同级另一处，也可以勾选“不迁移”连其中的项目和子分类一起从 Raptim 移除（原文件不动）；迁移时同名分类自动编号，空的默认分类不保留。至少保留一个分组，两种删除方式都受此约束。不再显示虚拟“全部”；没有子分类的分组自动建立默认分类，落在分组上的项目迁入真实分类。
- 标题栏搜索按钮或 **Ctrl+F** 打开主窗内搜索浮层；支持名称、别名、备注、多关键词、拼音和首字母匹配，按相关度排序。上下键选择、Enter 启动，Esc 分层关闭；输入法组合期间的 Enter 只结束组合，不会把半成品提交去启动。
- 设置按“常规、呼出与隐藏、游戏勿扰、数据、关于”排列；常规页另有开机启动（写当前用户注册表的 `CurrentVersion\Run`，值里带上 exe 与 `--data-dir`，默认关闭——挪过 exe 或换过数据目录就要重新开关一次）、启动方式（单击／双击）与悬停切换分类（停在分组上不点击即自动切过去，延迟 200／350／600 ms 可选，默认 350）；游戏勿扰页可选开启保护判定记录，写入数据目录并做路径脱敏，供排查游戏时被误呼出；右侧去掉重复页标题，使用紧凑等高行。开关和选择立即保存，文本仅保存合法输入。
- 贴边离开 150 ms 后收纳，悬停 40 ms 后展开；使用保留反向速度的阻尼动画，完整收纳约 155 ms、展开约 180 ms，短距离自动提前停稳。贴边状态下热键、托盘和第二实例也平滑展开；动画按刷新节奏更新，停稳或隐藏后停止。失焦等待 100 ms 后淡出 100 ms；系统关闭动画时直接切换，固定、编辑、菜单和拖放期间暂停收纳。
- 可开启/关闭露边，宽度可在 **1–12 个物理像素**间调节，默认 1；关闭后仍可悬停原窗口对应的边缘唤出，也可用热键或托盘找回。
- “更多 → 路径转换”提供分组/分类树形多选、全选/清空、半选状态及转换预览。以数据库目录为基准，同时转换程序路径和工作目录，跨盘失败保留原值。
- 每套菜单都按操作语义插入分隔线分段：项目右键为 打开／打开所在位置／复制路径 → 编辑／重新定位 → 管理员打开／原生菜单／桌面快捷方式／刷新图标 → 移动到／复制到 → 排序／路径转换 → 删除；分组右键为 新建／编辑 → 排序 → 删除，分类右键是同一形状再多一段 移动到分组（子分类能整体换到另一个分组，分组自己没有去处）；“数据”子菜单把 打开数据目录 与 导出／恢复 分开；托盘分成 窗口／开关／应用／退出 四段。窄窗口的项目区几乎点不到空白，所以空白右键那一段（多选整理／添加项目…／添加文件…／图标大小／列表查看／按名称排序）由同一处构造，同时挂在空白右键和标题栏“更多”里，命令号 30 与 40–46 共用一份分发。“更多”独有的部分是 数据／路径转换 → 恢复窗口位置／设置 → 退出；“恢复窗口位置”与托盘同项，取消贴边收纳并按当前尺寸把窗口居中回最近显示器的工作区（不抢焦点），用来救“位置记在已经拔掉的显示器上”这种情况。原生菜单按鼠标物理坐标定位，二级默认向右展开，仅屏幕边缘空间不足时由 Windows 翻转。
- 添加/编辑窗口采用单页滚动表单，名称/图标/分类、目标/参数/工作目录、别名/备注分区排列，不再折叠更多选项；程序与快捷方式另提供普通／最大化／最小化的打开方式，其他类型不显示该字段。所属分类改为分组→分类的树状选择（与批量整理共用同一棵树），支持展开收起、方向键与 Enter，Esc 只收树不丢编辑。类型为“应用”时目标不再手输：点“从应用列表选择”打开本机 AppsFolder 列表，可按名称或标识筛选，双击或”添加”即回填，并顺带取回该应用自己的图标；这个列表窗口跟随编辑器，不会把停靠条带到前台。删除确认显示对象名称、迁移目标或“不迁移”勾选，以及文件保留说明。
- Explorer 文件拖入、多选添加，程序/文件/目录/网址/快捷方式/AUMID，优先 256 像素的 Shell 图标提取（打包应用按 AUMID 从 AppsFolder 取图标，网址联网取网页自己的图标：`<link rel=icon>` 优先，退到 `/favicon.ico`）和自定义内嵌图标，JSON 导出与恢复继续支持。网址图标只在添加/编辑保存、拖入之后和手动“刷新图标缓存”时抓取，启动回填不联网。
- 关闭按钮隐藏；默认 **Ctrl + Alt + Space**、托盘或第二实例找回。可在“呼出与隐藏”录制新组合键或恢复默认；注册冲突时保留原设置。固定会置顶；游戏保护优先于固定和所有动画。

项目网格不再保留点击或右键选中高亮，搜索键盘导航仍显示当前结果。拖动需按住至少 180 ms 并移动至少 12 DIP；快速大幅滑动松手取消操作，菜单关闭清除指针状态。

主窗操作提示在 6 秒后自动消失，也可点击关闭。排队中的提示不逐条播放：一次只显示最新一条，其余折进“（另有 N 条提示）”，内容完全相同的一条被提到最新而不另计一条，队列上限 8 条，被挤掉的数量记作“，已省略 M 条”。拖动项目的左右半区分别表示插入目标之前/之后，插入线提示位置。

项目编辑仍保留未保存保护；删除和恢复仍需明确确认。相对路径以数据库目录为基准，数据页的“新增项目优先使用相对路径”开关决定新条目是否先写成相对形式。启动失败区分目标已删除、网络位置暂不可用、设备未就绪、无关联应用与已取消授权；其中“路径现在指不到”的四类——已删除、网络不可用、设备未就绪，以及校验就没通过的无效路径——就地提供重新定位，只替换路径，保留参数、工作目录与打开方式，并丢弃属于旧目标的内嵌图标；取消授权、权限被拒、没有关联应用和未分类的系统失败只留提示，不弹面板（面板只对还有文件路径可改的目标打开）。没有 Everything、磁盘索引、账号、云服务或皮肤。

## 数据恢复

业务数据与设置保存在 `raptim.db`。应用**不再提供内置备份**：要备份就退出应用后把整个数据目录复制走——`raptim.db` 必须连同同名的 `-wal`／`-shm` 一起，运行中只复制主文件会漏掉还在 WAL 里的数据；“导出”给的是另一份跨机器可用的 JSON。

数据目录里的 `error-log.txt` 是常开的：启动失败、没有区域认领的菜单命令和 panic 都会各写一行，带毫秒时间戳并做路径脱敏，超过 512 KiB 就从开头截断。发布版不附控制台，这里几乎是唯一的文字故障记录；它和要在设置里显式开启的保护判定记录（`protection-log.csv`）不是一回事。数据目录定下来之前发生的错误只能进对话框。

“恢复”只接受本应用版本 2 的 JSON，确认后替换当前数据。替换本身在一个事务里，失败自动回滚，但成功后**不再自动留一份旧库**（应用内备份已删掉），所以确认框要求你先自己备份。数据库 `.db` 副本只能在退出应用后整份复制数据目录得到；想先验一眼再决定，可以把副本放进一个**新的空目录**、命名为 `raptim.db`，用 `--data-dir` 打开它，原数据目录不受影响。确认框之前还有一道判定：JSON 里同一分类的两条目标只要**归一化之后**指向同一个文件（例如一条写成绝对、一条写成相对），就会被拒绝并点名其中一条——这一口径与 `dup_key` 列用的是同一个函数，不是导出文本的逐字比较。已有撞车对的库仍照常打开：本项目不做修复，只防新增。

导出不覆盖已有同名文件，请使用新名称。本项目不导入任何旧版数据；未知 JSON 字段/类型和非版本 2 的数据库一律拒绝读取、不作改写。

## 数据兼容与当前边界

数据库与 JSON 导出都是版本 2，Raptim 只读写版本 2。版本号随“这是新软件”的定位归零重开，因此 0.3–0.5 开发阶段留下的库、版本 1 的库、任何其它版本号的库和外部结构的库都会被拒绝且不作改写；设置项允许缺字段（读取时取默认值），但不接受未知字段。

版本 2 只改存储形状，不改功能：项目的 PNG 图标从 `entries.payload` 的 JSON 文本里搬到独立的 `icon BLOB` 列，另加一列 `dup_key`（把“同一分类不得重复目标”的判定键在写入时物化，因为归一化要相对化路径、解析 URL 并做全 Unicode 小写，SQLite 表达不了）。`payload` 因此不再包含图标，重复目标校验也不再读全表。今天每一条会改目标的写入路径——编辑、拖入、批量移动、重新定位、路径转换、迁移、恢复导入——都问同一个判定、用同一个键；`update_targets_checked`（重新定位与路径转换的落库点）曾是唯一没问的那条，它写出的撞车行会让下一次启动直接拒绝打开这个库。索引保持普通索引：`batch_entries` 在一笔事务里逐行改写，UNIQUE 会在合法的中间态上先行中止，把一个可读的中文错误变成一次不透明的回滚。JSON 导出里 `icon` 改为 base64 字符串（`Vec<u8>` 的默认序列化是每个字节一个十进制 token，约 3.6 个字符/字节）。实测同一份 300 条 / 7.34 MB 图标的数据集：启动到首帧 294.6 → 161.4 ms，`Store::open` 的全表读 187.8 → 27.8 ms，铺 300 条 33.9 → 0.35 s，空闲 private 23,970 → 19,466 KB。

本项目不做旧版数据迁移。浏览器/OLE 已有原生格式与生命周期回归，真实浏览器拖放、混合 DPI 和显示器热插拔仍需人工验收。游戏保护保留现有 500 ms 复核和显示前检查；尚未做 osu!lazer 真机矩阵。Narrator、高对比度、热插拔显示器及真实跨 DPI 鼠标操作仍需要人工验收。

应用上下文菜单使用 Fluent 自绘图标、文字、浅深色、悬停圆角与弹窗裁剪，Windows 负责菜单跟踪和三级展开；“Windows 原生菜单”单独调用 Shell，控件浮层由 Slint 绘制，托盘继续使用原生菜单；隐藏再呼出保留完整重绘桥接。内部桥接仍固定 Slint 1.18.0。

## 开发验证

默认验证路径全程不需要前台窗口：

```powershell
.\scripts\verify.ps1                      # 格式检查 + clippy(-D warnings) + 单元测试 + release 构建 + exe 体积
.\scripts\verify.ps1 -Release             # 同一批门禁，clippy 与测试也走 release profile
```

- `cargo fmt --check` 与 `cargo clippy --all-targets --locked -- -D warnings` 覆盖全部 Rust 模块。
- `cargo test --all-targets --locked` 运行数据存储、搜索、路径转换、停靠几何、显示策略及菜单命令路由等核心逻辑单元测试，不绑定具体 UI 坐标、像素色值或界面文案。
