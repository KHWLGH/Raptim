## 存储与启动实测

当前存储结构将项目图标从 `entries.payload` JSON 文本拆出到独立 `icon BLOB` 列，JSON 导出改为 Base64 编码，并在写入时保存去重键 `dup_key`（避免每次重复校验都扫描并反序列化全表）。

在同机同一组 **300 条项目 / 7.34 MB 合成图标** 数据集上的重构前后对比如下（提交 `764b608` 记录）：

| 指标 | 重构前（图标以 JSON 整数数组内嵌于 `payload`） | 当前实现（独立 `icon BLOB` + 物化 `dup_key`） | 变化 |
| --- | ---: | ---: | --- |
| `Store::open` 全表读耗时 | 187.8 ms | 27.8 ms | ↓ 85.2% |
| 启动到首帧呈现耗时 | 294.6 ms | 161.4 ms | ↓ 45.2% |
| 300 条数据铺库写入耗时 | 33.9 s | 0.35 s | ↓ 99.0% |
| 空闲状态 Private 内存 | 23,970 KB | 19,466 KB | ↓ 18.8% |

同一方案在 **300 条 / 2.98 MB 真实图标** 样本库上实测启动到首帧为 **138.8 ms**，空闲 Private 内存为 **17.2 MB**。

## 图标管线与内存控制

- **缩略入库（`STORE_MAX = 128`）**：本地 Shell 图标提取优先尝试 `SHIL_JUMBO`（256 px）以保清晰度；无论是文件提取、自定义图片还是网页图标抓取，落库前都会降采样至最大边 **128 px** 的 PNG（项目网格最大逻辑尺寸 48 px，足够覆盖高 DPI 显示）。即使库中存在大于 128 px 的图标数据，解码阶段也会统一缩放到 128 px。
- **就地回填，不整库重载**：后台批量补全或手动刷新图标后，通过 `Store::save_icon` 仅更新单行 BLOB 并就地替换内存中的 `entries` 与指纹键（`IconKey`），同时仅使相关条目重新进入可见带解码，避免整库重新读取与整列表刷新（回填每批从 O(N × blob) 降为 O(16)）。
- **按行虚拟化与 24 MiB 解码缓存**：
  - 主网格与搜索结果列表仅对当前视口及上下预留带（最多收集 224 个可见条目 ID）请求后台解码；离开视口的条目在网格模型中清空图片引用以释放纹理/像素占用。
  - `icons::Cache` 对解码结果及 36 px 拖拽缩略图（`ghost`）维护 LRU 缓存，字节上限 **24 MiB**（约覆盖 224 个 128 px 主图标及 36 px 拖拽图标约 16 MiB 再加富余量），超出即优先淘汰非可见项；当主窗口完全隐藏时立即收缩缓存至仅保留当前可见范围。

## 事件循环与渲染调度

- **搜索索引增量同步**：`SearchIndex::sync` 优先比对原始 `(name, aliases, notes)` 字段是否变化，未改动条目直接复用已有拼音/首字母文档而不重复分配字符串；搜索范围筛选结果按 `(scope, group, collection)` 缓存于 `eligible` 集合，仅在集合变化时重建。
- **差异化列表更新**：主列表与搜索结果使用 `ItemSignature`（除图标外的显示字段元组）比对，数据未变化时不整表重置 Slint `VecModel`。
- **按状态自适应唤醒**：
  - 主窗口、设置与编辑窗口均隐藏且保护态正常时，500 ms 常规巡检与交互定时器全部停止，第二实例改由命名事件异步通知，实现隐藏态零轮询。
  - 贴边收纳态鼠标在揭示带外 96 px 接近区之外时探测间隔为 **32 ms**，靠近边缘后切回 **16 ms**；未贴边失焦淡出阶段为 **8 ms**；贴边滑入/滑出动画交由高分辨率 `FrameClock` 对齐显示刷新节拍推进，动画结束即停止调度。

## 贴边改框写入与合成器边界

贴边展开瞬间曾出现圆角或阴影跳变，定位并清理了以下应用侧根因（提交 `740ea15`、`9483e39`、`54457f0`、`e486eab`）：

1. `decorate()` 与 `topmost()` 曾无条件重写 `GWL_EXSTYLE`、经由 winit 重设窗口层级/按钮掩码（导致 `WS_EX_TOOLWINDOW` 被抹掉并在下次显示时触发重新装饰）以及反复调用 `SetWindowRgn(NULL)`，不仅引起滑动期重建非客户区，还导致贴边一轮后窗体重新现身任务栏/Alt+Tab。
2. 现已将全部样式、区域、DWM 属性与层级改写改为对着 HWND 当前实时状态按需判重，拦截 `WM_STYLECHANGING` 阻止 winit 抹除工具窗口标记，并在贴边窗口外侧引入 `DOCK_OVERHANG_DIP = 10.0` 过伸使贴边侧系统圆角保持在屏幕外。

在真机窗口链路上实测改框计数结果如下：

| 窗口状态 | 收起改框写入 | 展开改框写入 | 说明 |
| --- | ---: | ---: | --- |
| 默认非置顶层级 | 1 笔 | 1 笔 | 仅动画起点临时升置顶与展开结束交回层级两次 |
| 开启「窗口始终置顶」 | **0 笔** | **0 笔** | 整个收起与展开滑动全程无任何样式、区域或层级写回 |

由于开启「窗口始终置顶」后本进程在滑动期间已实现 **0 笔** 改框写入，但桌面上在高速逐帧挪动窗口时仍可偶发观测到单帧圆角遮罩错拍，因此确认残余现象属于 **Windows DWM 合成器圆角遮罩与逐帧窗口位移动作之间的同步错帧**。本项目明确不与合成器逐帧对抗，仅保证应用侧在滑动期间除必要层级切换外不重建窗口框。

## 已验证并否决的方案

以下优化方案已在同机夹具上经实测否定并写入代码结论（提交 `764b608`），后续维护不应重复引入：

- **提高优化等级至 `opt-level = 2`**：换取仅约 1.2 ms 收益的同时导致二进制体积暴涨 +6.45 MB，且实测单帧耗时反而变差；维持 `opt-level = "z"`。
- **隐藏态调用 `EmptyWorkingSet`**：仅将任务管理器显示的 Working Set 表面压低至 ~435 KB，而实际 Private 提交内存纹丝不动，无助于降低真实内存占用，且唤醒后引发额外缺页中断。
- **限制 SQLite 页缓存 `PRAGMA cache_size = -4000`（4 MiB）**：由于图标 BLOB 列体积已超出 4 MiB，限制页缓存反而使 `Store::open` 全表读耗时翻倍（27.8 → 56.5 ms）；继续保持 SQLite 默认约 12.5 MiB 页缓存。
- **动画期主动设置 `SetWindowRgn` 裁剪**：对完全位于可见工作区内的窗口强制安装 HRGN 会关闭 DWM 抗锯齿圆角并造成高 DPI 锯齿边缘；现仅在多屏跨界会漏出邻屏像素时才按工作区矩形裁剪。
